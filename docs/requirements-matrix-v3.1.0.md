# v3.1.0 需求依赖矩阵

目标：保留 v3.0.0 的证据、视觉与 Word 同源生产内核，修正“把单个封板候选人的素材组合泛化为默认画像”。信息架构随真实证据与 JD 变化，个人主页、GitHub、Vibe Coding／其他项目和照片都不是必配项。

## 不可变量

1. 视觉标准保持思源宋体＋思源黑体，强调色 `#2F5BEA`；生产链保持结构化正文 → DOCX → Microsoft Word PDF。
2. 可变的是证据选择、章节有无、顺序与详略，不是事实状态、归属和真实验收口径。
3. 个人主页、GitHub、任何项目、照片均可省略；缺失不自动构成能力不足或 JD 缺口。
4. 已配置的内容必须真实完整；未配置与“配置了但丢失”必须严格区分。
5. 不生成空白链接行、空章节或占位项目；不为凑页数删字、缩字号或补入低相关内容。
6. 公开仓库不包含真实简历数据、本机私有路径或生产证据；旧版本仅在 Git 历史中回滚。

## MVP 切片

1. **基线保留**：v3.0.0 的证据、归属、固定视觉、Word 同源、全文对账、像素与编辑—撤销门禁继续通过。
2. **MVP-4｜候选人适配**：先写无链接、无项目、无照片及“已配置但丢失”的负样本，再实现可选内容和条件 QA。
3. **双夹具真实验收**：公开丰富虚构样例验证可选功能仍工作；另一极简虚构样例验证没有这些功能时仍是一份完整简历。
4. **发布**：同步 SKILL、Lite、README、需求矩阵、反方评审、项目页与脱敏 QA；推送 main、v3.1.0 标签并线上核验。

## 明确路由出去

- 学术 CV、设计作品集、政府／联邦格式、复杂图表简历。
- ATS 打分、自动投递、招聘平台对接、面试题库、录用或薪资预测。
- 把没有个人主页、GitHub、Vibe Coding 或照片解释为普遍能力短板。
- 无 Microsoft Word 时生成“替代引擎但冒充同源”的 PDF。
