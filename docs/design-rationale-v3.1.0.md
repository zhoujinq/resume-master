# v3.1.0 设计论证：稳定标准，不预设候选人

## 1. 最强反例先出现：v3.0.0 在哪里仍然错了

v3.0.0 解决了多主题、事实漂移和假验收，却仍把一个成功样本的素材组合带进了通用叙事：公开样例有个人主页、GitHub、项目与照片，工作流也重点描述这些对象。虽然 schema 技术上允许省略，但 Agent 很容易把“样例里都有”理解成“好简历都应该有”。

这暴露了一个比文案更本质的问题：**实现上的 optional，不等于产品语义上的 optional。** 如果测试只覆盖功能丰富的样例，缺失场景会出现空白段落、误导性的 0/0 通过，或把可选项当成缺口。

v3.1.0 因此不是删除 GitHub 或项目能力，而是同时验证两种完整候选人：一种有这些证据，一种完全没有。两者共用同一生产内核，不是两套模板。

## 2. 第一性原理：资深猎头到底在优化什么

招聘方要在有限注意力内判断四件事：岗位相关性、证据可信性、个人贡献可答辩性、信息可读性。简历是支持这次判断的**决策文档**，不是候选人的资料清单，也不是互联网身份展示页。

由此得到五条推导：

1. **证据载体不等于证据本身。** 个人主页、GitHub、Vibe Coding 项目、竞赛、证书都只是可能承载证据的容器；容器名称不能替代真实动作与结果。
2. **缺失不等于零分。** 没有公开链接，可能只是工作不可公开、岗位并不需要或候选人选择不展示。除非 JD 明确要求，否则它是不适用，不是负面事实。
3. **章节有注意力成本。** 一个低相关项目会挤占高相关工作成果的位置。章节是否保留，应看它对目标岗位判断的增量信息，而不是为了页面看起来完整。
4. **统一的是判断秩序，不是人生路径。** 字体、层级、事实口径和文件验收可以稳定；章节有无、顺序、详略和职业叙事必须随证据变化。
5. **可选项也必须防止假缺失。** 未配置链接可以 N/A；配置了链接却在 DOCX／PDF 中丢失必须 FAIL。否则“可选”会成为掩盖渲染 Bug 的借口。

顶尖猎头会先看真实 JD、工作经历、可核验结果、角色归属和面试追问，再决定是否值得加入作品链接或项目；不会先要求每个候选人补一个 GitHub 或 Vibe Coding 项目。

## 3. 重新评估后的架构：稳定内核＋按需信息架构

### 稳定内核

- `facts` 保存来源、确认状态、归属和答辩说明；正文 bullet 引用事实 ID。
- 视觉继续使用 V53.1 的字体角色、`#2F5BEA` 与克制密度。
- 结构化正文只走 DOCX → Microsoft Word PDF；实际产物接受全文、链接、字体、坐标、像素和编辑—撤销验收。

### 按需信息架构

| 内容 | 何时出现 | 没有时 | 配置后异常时 |
|---|---|---|---|
| 个人主页／GitHub／其他链接 | URL 真实且能增加岗位判断信息 | 省略整个链接区，不留空段 | 缺 URL、DOCX／PDF 丢失或出现额外链接即 FAIL |
| Vibe Coding／其他项目 | 项目本身能证明目标能力，且候选人可答辩 | 不生成项目章节，不自动记 gap | 空项目章节被校验阻断 |
| 照片 | 用户主动提供并确认使用 | 题头横线延伸至右边距，照片检查 N/A | 配置后图像缺失、裁切或坐标异常即 FAIL |
| 作品集要求 | JD 明确要求且相关 | 仅在此时如实披露真实缺口 | 不用虚构项目填补 |
| 工作／教育／技能等章节 | 有实际内容且服务目标岗位 | 按事实选择，不追求固定目录 | 空标题不能进入终稿 |

### 条件式 QA

`NOT_APPLICABLE` 表示该对象从未配置，因此检查不适用；`PASS` 表示配置对象经过真实核对；`NOT_RUN` 表示应执行而未执行；`FAIL` 表示配置与实际不一致。四者不得混用。

公开丰富样例继续验证 6/6 链接、照片和项目没有因“可选化”被删坏；独立极简虚构样例验证无个人主页、无 GitHub、无任何项目、无照片时没有空段、空章节或误导性通过。

## 4. 跨领域机制：为什么这是更优解

| 领域 | 可复用结论 | 本版对应机制 |
|---|---|---|
| 医学检查 | 检查应由症状和鉴别问题触发，不是项目越多越好 | 只有能改变岗位判断的证据才进入；不适用检查不扣分 |
| 缺失数据方法 | 缺失不是 0，也不能随便插补 | 链接／项目缺失为 N/A；不编造占位内容 |
| API 与数据库契约 | optional 字段缺省与 null／空字符串语义不同 | 未配置、空配置、配置后丢失分别处理 |
| 信息检索 | 高相关少量结果优于堆满低相关结果 | 章节按 JD 增量信息排序，避免完整资料清单 |
| 渐进披露 | 复杂信息按需出现，降低首屏认知负担 | 链接、项目、照片按需出现，不设固定目录 |
| 组合测试 | 功能存在与缺失都可能触发缺陷 | 丰富＋极简双夹具，另测配置后丢失与空章节负样本 |
| 航空检查单 | 不适用不能伪装成已执行 | N/A、PASS、NOT_RUN、FAIL 独立呈现 |

## 5. 最强反对者：继续试图推翻 v3.1.0

| 反对证据／反例 | 能推翻什么 | 重新评估后的处理 |
|---|---|---|
| 技术、设计岗位常需要作品，完全不提示可能损失机会 | “链接和项目永远不重要” | 可选不等于不重要；JD 明确要求时记真实 gap，相关项目仍应优先 |
| 转行者、应届生可能主要靠项目证明能力 | “无项目章节更高级” | 不鼓励删除高信号项目；是否保留由证据增量决定，而非资历标签 |
| 把链接 QA 设为 N/A 可能掩盖链接生成故障 | “0/0 就能证明可选支持” | 仅源数据未配置且双端均无链接时 N/A；配置后缺失仍 FAIL |
| 功能丰富样例继续存在，Agent 仍可能照抄其章节 | “加一句可选声明就解决了” | 极简真实产物、空章节阻断、双夹具测试和 Skill 明确规则共同约束 |
| 无链接后删除一个段落可能改变分页 | “DOCX 结构测试足够” | 极简样例实际经 Word 导出，检查页数、页底、全文和逐页像素 |
| 允许章节自由组合会重新引入版式漂移 | “只有固定目录才能稳定” | 自由的是内容架构；字体、字号、色彩、段落角色和导出路线仍固定 |
| 极简候选人一页很空，是否应自动补项目 | “填满页面才专业” | 不补低相关内容；末页留白只做建议，不用虚构项目换视觉饱满 |
| 公开链接无法打开时怎么办 | “URL 存在就等于有效证据” | 当前 QA 只核对双端关系与字符串，不声称公网内容真实；可访问性与归属另需用户确认 |
| 无照片可能不符合某些地区或岗位惯例 | “照片永远应该省略” | 照片保持用户选择；只保证无照片不构成系统缺陷 |
| 双夹具仍覆盖不了所有职业与超长经历 | “两个样例就能证明通用” | 双夹具只证明本轮边界；长文、长 URL、缺 Word、暂定事实等负样本继续保留 |
| 视觉标准本身仍可能不适合设计简历或学术 CV | “稳定内核就是全行业最优” | 明确路由出去；最优是限定场景内可靠，而非假装覆盖所有简历 |

## 6. 最终判断

v3.1.0 的更优解不是“进一步减少内容”，而是**不把任何特定候选人的素材组合上升为普遍要求**。招聘判断需要高信号证据，证据可以来自工作、教育、技能、项目或外部链接；没有某类载体时，简历仍然可以完整、可信、专业。

因此保留 v3.0.0 的真实性、可编辑性和真实产物 QA，新增三条硬约束：可选内容缺省无空区、条件检查不误判、丰富与极简双夹具同时通过。方案仍不能保证面试或录用，也不能自动证明公网链接内容真实；这些边界必须随交付保留。
