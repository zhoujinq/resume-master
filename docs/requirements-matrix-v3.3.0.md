# v3.3.0 需求依赖矩阵

目标：保留封板前的证据生产链，在第一个封板大版本验收后，生成可交互、可编辑、可自动保存的单文件 HTML。用户可自己微调文字、加粗、文字颜色、字号、行距与段距，并从当前编辑状态导出真实 DOCX 和浏览器 PDF。

## 生命周期与不可变量

1. **封板前**：事实台账＋定向正文 → DOCX → Microsoft Word PDF；不从 HTML 初排，不恢复多版式。
2. **封板后**：最终 YAML＋对应 PDF＋封板 DOCX＋QA → 派生编辑 HTML。PDF 是可见内容基准，YAML 提供稳定结构，封板 DOCX 提供原位导出模板；不把 PDF 坐标碎片直接冒充段落。
3. 初始视觉仍为思源宋体＋思源黑体、`#2F5BEA`；只有封板后的个人副本允许用户覆盖局部样式。
4. 个人主页、GitHub、任何项目和照片仍为可选项；缺失不生成空区，配置后进入编辑器与导出时不得丢失。
5. 编辑器默认本地运行、无运行时外部请求；自动保存不是唯一备份，必须支持导出／导入编辑数据。
6. HTML 与浏览器 PDF 的字号、行距、段距按 0.1pt 调节；标准 DOCX 字号只能按 0.5pt 存储，导出必须提示取整，不能虚称 0.1pt 无损。
7. 手动修改事实不会被系统锁死，但数字词元变化必须提示重新核验；编辑器不输出真实性、面试率或质量分数。
8. 公开仓库只使用虚构样例，不包含真实简历、私有路径或生产数据。

## MVP 切片

1. **基线保留**：既有生产链、写作门禁、双候选人与真实 Word QA 不回退。
2. **MVP-6｜封板派生**：先实现 YAML＋PDF＋QA 门禁和编辑器状态，再实现直接编辑、格式控制与本地保存。
3. **MVP-6｜最新状态导出**：实现真实 DOCX、浏览器 PDF 与数据备份；用修改后的文本证明导出没有回到旧版。
4. **真实验收**：在浏览器完成文字／Ctrl+B／颜色／0.1pt 调整，下载 DOCX 并用 Microsoft Word 打开、编辑—撤销及导出 PDF。
5. **发布**：同步全部入口、需求矩阵、反方论证、项目页和脱敏 QA；推送 main、v3.3.0 标签并线上核验。

## 明确路由出去

- 一开始就绕开事实生产链，用 HTML 初排简历。
- 只有 PDF 而没有结构源时，自动猜段落、归属或阅读顺序；应先抽取并人工确认结构。
- 把编辑器当成多人协同、云端账号、版本分支或 ATS 评分系统。
- 声称 DOCX 支持 0.1pt 字号，或把浏览器打印按钮说成服务器直接生成 PDF。
- 为了排版自由恢复三种主题，或把缺失主页／GitHub／项目／照片当成普遍短板。
- 机械数字检查替代人工事实复核，或承诺打印结果在所有浏览器与 Word 中逐像素一致。
