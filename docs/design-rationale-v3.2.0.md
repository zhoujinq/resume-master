# v3.2.0 设计论证：让事实更像候选人说的，而不是换一套 AI 腔

## 1. 本轮实际研读了什么

本轮完整阅读了秋芝2046《像高手一样做自己的 Skill！【小白教程】》正文及 48 张配图，并审查用户提供的 Humanizer ZIP：`SKILL.md`、README 和 MIT 许可。Humanizer 版本为 4.0.0，归纳 26 类英文写作模式。

来源：

- 文章：https://mp.weixin.qq.com/s/W7QNA9Xk2L-UTOaHO8iGvQ
- Humanizer：https://github.com/blader/humanizer

文章与配图带来的有效方法不是“再下载一个 Skill”，而是：先裸跑确认问题，寻找底子，用真实样本提炼 KEEP／CHANGE／ADD，逐句评论，把主流程与参考拆开，同题对照，在使用中删减规则。配图还明确指出，检测计数不是写作配额，命中需要人工判断。

## 2. 最强反例：直接叠加 Humanizer 为什么会失败

1. **英文规则不等于中文简历规则。** 英文破折号、被动句、标题大小写和连字符规则不能机械移植；中文简历日期范围本来就需要连接号。
2. **去 AI 味可能制造新的 AI 味。** 把“不仅……更……”统一替换成另一组口头禅，只是换模板。
3. **简历不是自媒体文稿。** 固定开场、波浪号、口语化结尾和情绪化表达可能损害专业可信度。
4. **风格优化可能篡改事实。** 删除数字、弱化归属、把“协助”改成“主导”，比套话本身更严重。
5. **强制十篇样本会阻断材料少的候选人。** 十篇不是启动门槛；没有样本时仍可保持中性、简洁、具体。
6. **命中更少不代表简历更好。** 规则可以被迎合，检测器分数也不等于招聘方判断。

因此 v3.2.0 不复制 26 条禁令，也不追求“零命中”。它抽取底层机制：直接陈述、按读者提供增量信息、保持事实、用真实样本校准、弱信号人工判断、同题对照。

## 3. 第一性原理：简历里的“人味”是什么

简历是招聘决策文档。所谓人味，不是随意、口语或故意不完整，而是读者能看见一个具体的人：他做了什么，做到什么程度，与谁协作，结果如何计算，哪些话能在面试中继续解释。

由此得到四条原则：

- **具体比修辞重要。** 每条 bullet 应提供对象、动作、边界、结果或口径中的真实增量。
- **候选人的可答辩性高于作者的风格表演。** 不为了像人而添加情绪、猜测或口头禅。
- **风格只能改变表达层。** 纯润色只能改变 `bullet.text`；事实台账、归属、URL、结构和其他字段不变，数字不增不减。
- **自动检查有明确上限。** 字段和数字可以机械对账，名称、动作和因果关系是否等价仍需人工阅读。

## 4. v3.2.0 架构：三层写作保障

### A. 结构套话提示

检查铺垫对比、戏剧化开场、空泛深刻、夸大意义、无名权威、抽象三连、破折号滥用、堆叠限定、对话残留、文档自叙和猜测性事实。每项返回位置、原因与处理规律，不返回总分。

强阻断只用于终稿本就不该出现的内容，例如“希望这份简历对你有帮助”“本简历旨在”“大概参与了”。真实对比、专业术语和弱模式只给 WARN，由执行者决定保留或重写。

### B. 改前改后事实对账

`content_audit.py revised.yaml --baseline before.yaml` 执行两层检查：

1. 除 `bullet.text` 外的结构必须完全一致，防止事实、归属、URL、事实 ID 或配置在润色中漂移。
2. 对应 bullet 的数字词元多重集必须一致，防止新增或丢失数字。

两项通过只叫机械对账通过。正文发生变化时，始终保留人工语义复核提醒，不能声称自动证明原意不变。

### C. 可选表达样本与同题对照

有用户本人文本时，提取句长、用词、标点、开头和转折，并附原文证据，分成 KEEP／CHANGE／ADD。样本只校准表达，不覆盖事实、专业性和固定视觉。没有样本时使用中性专业风格。

评估 Skill 时固定同一原始材料、JD、模型和任务，再比较无 Skill、通用 Humanizer 与 resume-master。自动负样本、机械对账、真实 Word 验收和人工盲评是不同证据层；未执行人工盲评就不宣称胜出。

## 5. 跨领域复核

| 领域 | 可复用机制 | 本版对应 |
|---|---|---|
| 软件 lint | 规则解释问题与修复方向，误报需要上下文 | 结构模式 WARN＋处理规律，不按命中数评分 |
| 数据库事务 | 只有指定字段可写，其余保持不变 | 纯润色仅允许 `bullet.text` 变化 |
| 药学剂量核对 | 成分相同不代表临床效果相同 | 数字对账不冒充语义等价 |
| 实验对照 | 同输入、同条件、盲评，避免先入为主 | 同题评估协议与证据分层 |
| 风格指南 | 风格服务读者和文体，不是个人癖好展示 | 招聘方可读性优先于口语化 |
| 渐进披露 | 主流程短，细节按需加载 | SKILL 只留门禁，写作细节进入 references |

## 6. 最强反对者继续攻击本方案

| 反对证据／反例 | 重新评估后的处理 |
|---|---|
| “动作＋对象＋结果”本身也会模板化 | 公式只用于检查信息是否完整，不要求所有 bullet 同序、同长或都有数字 |
| 真实归属对比可能出现“不是……而是……” | 对比只 WARN；若用于澄清真实误解可保留，不自动改写 |
| 用户确认的原话也可能命中套话 | 已确认措辞优先；报告提示但不静默覆盖，必要时由用户决定 |
| 相同数字并不能证明事实未变 | 明确保留人工语义复核，不把机械对账写成事实真实 |
| 警告太多会造成疲劳，最后被忽略 | 强阻断只覆盖明显残留与猜测；弱模式用于定位，正文仍以招聘增量为准 |
| 个人样本可能包含不适合简历的聊天习惯 | KEEP／CHANGE／ADD 分类；样本不是无条件覆盖规则 |
| 没有十篇样本就无法提炼风格 | 十篇不是门槛；少样本标低置信度，无样本用中性专业表达 |
| 做三组 Agent 输出就能证明质量 | 不能；需要盲化、同模型、同输入和人的评价，且结果只适用于测试样本 |
| 风格审计能否保证更高面试率 | 不能；不承诺面试、录用或 AI 检测结果 |

## 7. 最终判断

v3.2.0 采用“稳定证据与生产内核＋按需信息架构＋可审计写作复核”。它吸收 Humanizer 的结构思维与文章的真实任务迭代方法，同时拒绝全局禁令、强制个人语料和检测器导向。

最本质的优化不是让文字看起来像某个人，而是让每一项表达都能回到候选人的真实经历与答辩能力。能自动验证的严格验证，不能自动验证的诚实留给人。
