# 2026-11-20—11-24 返工复盘：从事件清单到共同根因

## 结论

本阶段已识别 15 类可预防问题。它们不是彼此独立的“粗心”，而是七个共同根因反复表现：**目标漂移、多个真相源、授权边界模糊、局部补丁替代架构修正、代理指标冒充真实结果、交接时丢失已确认状态、把单个成功样本的表象泛化为普遍要求。**

V53.1 最终收敛不是因为增加了更多路线，而是因为减少了自由度：用户锁定正文，DOCX 成为唯一排版源，PDF 由同一 Word 引擎导出，验收直接检查实际产物。v2 又保留多主题，说明旧架构的“可配置惯性”在重构后仍未被契约测试阻断；这是本版必须删除的回归。

## 事件、返工与根因对照

| 簇 | 实际表现 | 深层根因 | 必须自动阻断的回归 |
|---|---|---|---|
| P01 | 已确认事实在交接后被降级为“待核验”，接手者抛开成熟底稿重写 | 把“我没重新验证”误作“用户没确认”；交接只交方向，没有交生产链 | `E01` 状态不可降级；`H01` 冷启动交接契约 |
| P02 | 把用户未反对当成逐字确认，补入用户无法解释的技术维度 | 缺少确认、授权调整、暂定三态 | `E02` 暂定事实禁止进入终稿 |
| P03 | 强动词、技术词、大数字和强调色一度过多 | 把“看起来专业”置于真实归属和用户声音之前 | `E03` 归属动词检查；`C05` 强调清单契约 |
| P04 | 项目组合、主页与简历任务互相串线，旧建议覆盖最新指令 | 没有每轮对象、范围、唯一负责人和不可变量 | `H02` 最新指令覆盖测试；`H03` 非目标文件哈希不变 |
| P05 | 多版本、多项目组合、多排版路线并行，用户选择成本上升 | 把探索数量当作质量，未及时冻结一个候选 | `D01` 每岗位一个候选；`D02` 当前树只允许一个视觉标准 |
| P06 | 已提供的信息被重复询问，澄清方式与用户当下需要不匹配 | 流程完整性优先于用户已有上下文 | `H04` 已有事实不得重问；集中补问上限 |
| P07 | 长期把文字一致、页数正确当作 Word/PDF 视觉一致 | 验收围绕易脚本化指标，而非用户实际看到的结果 | `A01` 同引擎；`A02` 真实渲染；`A03` 字体／照片／线条／坐标 |
| P08 | HTML 与 DOCX 两套引擎分别排版，反复修补仍漂移 | 先修症状，没有先修生成架构 | `A01` 只允许 DOCX → Word PDF；旧渲染入口不存在 |
| P09 | 字体安装、注册、可变实例、子集等多轮试错，重启仍未解决 | 缺少最小决定性实验；把系统状态当作应用实际行为 | `A04` 字体白名单；`A05` 字重与文本层；`A06` 禁止系统变更 |
| P10 | Logo 撑行、照片裁切、页首间距失效、横线错位、小子集重排 | 把 CSS／Word 经验当规律，没有以实际行坐标复核 | `A07` 图片结构；`A08` 行距与页底；`A09` 横线／链接坐标 |
| P11 | QA 对相近符号、独立日期行、空白 span 产生假失败或假通过 | 比较器没有良好样本、负样本和自身测试 | `Q01` 已知良好／故意破坏样本；`Q02` 只规范化排版符号 |
| P12 | 多屏和窗口切换下，错误窗口截图进入证据目录 | 只验证“有截图”，没有验证截图对象 | `Q03` 证据必须含目标、页码、缩放与人工复核记录 |
| P13 | 把核心目标达成写成“全部严格通过”，隐藏未做和建议未达 | 汇总口径没有逐条映射原标准 | `Q04` 核心／严格／建议分离；`NOT_RUN` 不算通过 |
| P14 | v2 仍保留三主题和主题资产，用户从未使用却持续出现在网页 | 把旧功能保留当成默认正确；缺少“用户认可行为”反向契约 | `D02` 活跃文件禁止旧主题、旧强调色和 preset；`D03` 网站不得回退旧主题 |
| P15 | 把个人主页、GitHub、Vibe Coding／其他项目和照片写成默认候选人画像 | 把 V53.1 与公开丰富样例的可选素材误当普遍必备；只测“什么都有”的样例 | `E04` 可选内容缺失不报错；`A10` 无链接／无项目无空区；`Q05` 未配置为 N/A、配置后丢失仍 FAIL |

## 七个共同根因如何相互放大

1. **目标漂移**让“功能多”压过“证据可信、用户能答辩、打开不跑版”。
2. **多个真相源**让事实、正文、HTML、DOCX、PDF 和报告各自变化；局部修补越多，漂移越隐蔽。
3. **授权边界模糊**使 Agent 用个人审美替代用户判断，甚至把暂定内容写成事实。
4. **局部补丁思维**在错误架构上修边距、字体和符号，导致修复一处又破坏另一处。
5. **代理指标崇拜**用测试数量、参数、文件生成和截图存在代替真实可见结果。
6. **上下文与交接失真**把历史摘要当现实，把已确认状态重新打开，重复制造已经解决过的问题。
7. **成功样本过拟合**把某个人、某次封板或某个功能丰富样例中的可选特征，误写成所有候选人的默认目录。

因此，只增加更多测试数量仍可能失败。测试必须直接对应这些根因，并在发布前证明：**旧版无法通过，故意破坏样例也无法通过；功能丰富与功能极简的候选人都能通过。**

## V53.1 留下的不可变量

- 内容源与排版源分离：正文先冻结，DOCX 后成为唯一排版源。
- 用户确认过的事实、措辞和归属，不因换版本或换 Agent 自动降级。
- 正文 9.5pt，字号只取 0.5pt 整数倍；不为凑页数静默删字、缩字号或改顺序。
- 思源宋体负责姓名、模块标题与日期；思源黑体负责正文、条目、联系方式与链接。
- A4、左右 17mm、固定正文行距、真实超链接、照片等比且不使用固定行距裁切。
- PDF 由 Microsoft Word 从交付 DOCX 渲染；其他引擎不能冒充同源。
- 验收必须包含实际文本、字体、链接、页数、坐标、逐页视觉、重复导出和未做项。

本版唯一额外视觉变更是用户明确指定的强调色 `#2F5BEA`，替代历史封板中的蓝色值；其余版式从 V53.1 生产路径抽象，不发明第二套主题。

| 族 | 目的 |
|---|---|
| `D` | 删除多主题、多路线和无限探索，固定唯一视觉与生产链 |
