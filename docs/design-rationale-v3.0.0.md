# v3 设计论证：证据优先，而不是模板优先

## 1. 第一性原理：简历到底解决什么问题

招聘方面对的不是“这份简历美不美”，而是一个高噪声决策：在很短时间内判断候选人是否相关、证据是否可信、风险是否值得继续面试验证。

因此，简历质量可以理解为四个必要条件，而不是一个虚构 ATS 分数：

- **相关性**：目标岗位的重要问题，是否有对应经历回答。
- **可信性**：数字、角色、时间、结果能否追溯，个人／团队／协助／演示是否分清。
- **可答辩性**：候选人能否解释每句话，并在追问中提供相同口径。
- **可读性**：招聘方能否快速找到重点，文件打开后是否稳定、可编辑、可点击。

任何一个条件为零，视觉再精致也没有意义。顶尖猎头或 HR 会使用真实 JD、候选人经历库、可核验作品、时间线、角色归属、面试追问和定向修改记录；不会先让候选人从三种皮肤中选一种。

## 2. 最优工作方法

1. **建立证据台账**：每条事实有来源、确认状态、归属和可答辩说明。
2. **拆解 JD 的决策问题**：区分必要能力、加分能力、约束和仅用于检索的词，不输出伪精确匹配分。
3. **建立能力—证据映射**：一个事实可支持多个能力，但没有证据的关键词不得写成能力。
4. **形成一个定向候选**：按岗位重排证据与详略，不批量生产风格版本。
5. **做反向面试审查**：随机抽数字、技术词和角色动词，候选人不能解释就退回待确认。
6. **两次确认后冻结**：先结构，再全文与强调清单；最新指令只覆盖明确变化的部分。
7. **单一生产链**：结构化正文 → DOCX → Microsoft Word PDF；真实渲染、负样本和复现测试后再交付。

## 3. 跨领域可复用方案

| 领域 | 可借用机制 | 在简历 Skill 中的对应物 |
|---|---|---|
| 财务审计／复式记账 | 每笔记录有来源，总额必须能对账 | 每个数字与角色动词映射证据；源文、DOCX、PDF 对账 |
| 航空检查单 | 关键步骤不可凭记忆跳过 | 结构确认、全文确认、真实渲染、未做项门禁 |
| 医学鉴别诊断 | 相似症状先区分不同病因 | QA 失败分为文档问题、比较器问题、标准问题 |
| 软件 SRE／影子发布 | 先影子运行，再切换；保留回滚 | 虚构样例＋私有真实影子验收；旧版只在 Git 历史回滚 |
| 法律服务发现 | 证据与主张绑定，区分事实和陈述 | 事实状态、归属、来源和面试可答辩记录 |
| 供应链追溯 | 任一批次可回溯上游 | 每个交付文件保存源文件与哈希、工具链和验收报告 |
| 安全红队 | 主动构造绕过与失败路径 | 暂定事实、无来源数字、长 URL、无照片、缺字体、错误窗口等负样本 |

## 4. AIHOT 重写经验的正确用法

可复用的是：先蒸馏用户价值与已认可行为、规格驱动重建、模块化最小上下文、功能与 UX 对照、影子运行、独立端到端验收、保留回滚，并把重复根因转成规则。

不能机械照搬的是：为了“干净”而删掉用户已经认可的视觉或功能；声称没有读过旧实现的 clean-room；用代码审查代替线上与真实产物验收。本版属于**规格驱动重建**，因为构建前已经读取旧实现与 V53.1 生产脚本，不声称严格 clean-room。

## 5. v3 方案

### 内容层

- YAML 同时保存 `facts` 证据台账与 `sections` 定向正文。
- 每条含数字的成果 bullet 必须引用事实 ID；事实必须有来源、确认状态和归属。
- `provisional` 事实不能进入最终渲染；已确认事实派生新版本时状态不得自动降级。
- 归属词是事实字段，不是修辞选择。协助事实不得被改写成独立或主导成果。
- 台账只能证明“可追溯”，不能代替用户确认真实性。

### 视觉与生产层

- 只保留 V53.1 抽象出的一个视觉标准：思源宋体＋思源黑体，强调色 `#2F5BEA`。
- 删除主题 preset、其他强调色、HTML／浏览器 PDF、ReportLab 兜底及对应资产和示例。
- 正文不使用文本框，不用空格或软回车凑版；URL 是真实链接；照片与 Logo 不撑行、不裁切。
- PDF 只能由 Word 从同一 DOCX 渲染。无 Word 时可以生成 DOCX，但 PDF 必须标记 `NOT_RUN`，不能换引擎冒充。

### 验收层

- 核心：证据校验、源文覆盖、全文一致、页数与越界、字体、文本层、链接、照片结构、逐页视觉。
- 严格：第二次导出逐页像素差为 0、实际 Word 编辑—撤销、坐标与行距。
- 建议：照片像素、PDF 体积、末页留白。
- `PASS／WARN／FAIL／NOT_RUN／NOT_APPLICABLE` 分离；未做永不计入通过。

## 6. 最强反对者：怎样证明这个方案可能是错的

| 反对证据／反例 | 它推翻了什么 | 重新评估后的处理 |
|---|---|---|
| 学术 CV、设计作品集、联邦简历可能需要完全不同结构与页数 | “一个版式适合所有简历” | 本仓库明确定位于中文市场化岗位的简明简历；这些场景路由出去，不硬套 |
| 证据台账填写成本高，可能让只有旧简历的用户更慢 | “更多结构一定更好” | Agent 先从旧材料预填；未知项集中核对；只有终稿强制闭合，不在初读阶段反复追问 |
| 数字映射只能证明字符串有来源，不能证明来源真实 | “自动检查能保证事实真实” | 明示它只做追溯与归属防漂移，用户确认和可答辩复核不可被脚本替代 |
| 固定版式遇到极长经历、无照片或长 URL 可能跑版 | “V53.1 参数可直接覆盖所有内容” | 允许省略照片和章节；不删字缩字号；超界即失败并报告，不自动美化成通过 |
| Word 不可用或跨平台用户无法导出 | “唯一路线就是普遍可执行” | 无 Word 时明确只交付 DOCX／正文与未完成 PDF，不恢复第二引擎 |
| 两次确认在极小修改上浪费轮次 | “所有任务都必须同样重流程” | 用户明确要求时可合并确认；事实、差异、真实渲染和未做项不可跳过 |
| 只做一个候选可能错过更好的叙事 | “禁止探索能提高质量” | 探索发生在证据映射和正文确认前，而不是同时生成多份成品；用户确认后只维护一个候选 |
| 照片可能带来地域／外貌偏见，某些市场不建议照片 | “V53.1 的所有元素都强制” | 照片可选；无照片不判定失败，页眉仍保持同一字体与秩序 |
| 蓝色与字体白名单可能受本机 Word 导出实现影响 | “参数写对就证明实际产物对” | 以 PDF 实际字体、颜色、文本层和视觉为准；不允许通过扩大白名单掩盖回退 |

## 7. 最终判断

最合理的方案不是“通用到能生成任何简历”，而是**在一个清晰适用范围内，把真实证据、用户声音和实际产物做得更可靠**。本版主动牺牲主题数量、渲染路线和伪智能评分，换取更少的漂移面、更强的追溯和可复现性。

仍需保留的边界：脚本不能判断经历是否真实，不能保证招聘结果，不能替代用户最终审稿，也不能证明所有机器上的 Word 都会产生相同分页。上述能力边界必须随交付一起出现。
