# 确认 1：结构线框先行

> 先决定阅读体验，再打磨文字。线框解决“先看什么、各块占多少、怎样好看”，不是用虚构内容填一张假简历。

## 一、线框必须包含

| 决策 | 要给出的内容 |
|---|---|
| 目标与页数 | 通用版或目标岗位；一页／两页及理由 |
| 章节顺序 | 各章节标题、先后、保留／合并／删除建议 |
| 页面配比 | 每页放哪些章节，各章大致条目数与篇幅预算 |
| 阅读顺序 | 招聘方第一眼、第二眼、最后应记住什么 |
| 条目布局 | 题头、联系方式、公司／职位／日期、项目链接如何排列 |
| 视觉方向 | `swiss`／`editorial`／`mono`，密度、是否照片、强调色 |
| 重点位置 | 哪些真实成果或能力进入首屏与强调区，哪些明确不强调 |

可用 Markdown 表格或简洁文本框表达，不必先渲染完整 PDF。不要填虚构姓名、公司、项目或 `【待补】` 来冒充正文。

## 二、默认呈现判断

1. **匹配优先**：有 JD 时，把最有证据的匹配内容放前；没有 JD 时按通用可读性组织。
2. **同类内容按时间倒序**：工作通常按时间倒序；项目先按目标岗位相关性，再按时间与证据完整度排序，若用户要求纯时间顺序则遵从。
3. **首屏必须有定位**：姓名／求职方向之后，尽快出现最能支持方向的经历或成果，不让长篇自我评价占位。
4. **重点少而清楚**：先拟重点位置，具体措辞和标蓝清单在确认 2 一并审定。
5. **页数是预算不是枷锁**：内容确认后可能膨胀，终排时允许重新分页，不能为了守住一页硬删事实。

## 三、确认后再写全文

输出线框后明确停在**确认 1**：请用户确认章节顺序、页面配比、视觉方向和重点位置。若用户提出修改，只更新线框，不提前写整篇正文。

用户确认后再进入确认 2，一次性写出全文。用户明确要求跳过确认时，可以连续推进，但仍要保留线框供回溯。
