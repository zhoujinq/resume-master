# 内容规则（写什么）

> 版式解决“看起来专业”，内容解决“为什么要你”。本文件是内容宪法，优先级高于模板。

## 一、一条 bullet 的信息优先级

```
业务问题 → 我的判断 → 我的动作 → 可验证结果
```

这是信息完整性的参考，不是必须套用的句式。优先补“具体对象、个人动作、可验证结果”；真实经历没有清晰判断或数字时，不硬凑。只有动作的 bullet 先尝试补信息，无法补就保留清楚事实或删减，不编造。

| 只写动作（弱） | 补足对象、动作与结果（较好，虚构） |
|---|---|
| 负责区域渠道开拓，开发若干客户 | 将区域客户按需求与采购阶段分层，用看板跟进；3 个月完成 18 家有效接洽、5 家付费转化 |

“判断”若出现，应是能被追问的真实选择，不是套话。写不出判断时，不必强行拔高；清楚的对象、动作和结果同样有价值。

## 二、量化：先确认口径

按可信度从高到低选：

1. **业务数字**：回款、签约、营收、留存、转化、耗时；
2. **规模数字**：客户数、团队人数、品类数、文档份数；
3. **相对数字**：同比、环比、从几步到几步，必须写基线；
4. **范围描述**：负责哪个区域、哪些客户、哪段时间。

每个关键数字检查：**统计周期、覆盖范围、个人／团队归属、结果类型、比较基线**。签约、回款、营收、GMV 与在途商机不混写。

**禁止**：编造数字、把“参与”写成“主导”、把团队成果写成个人成果、把整体增长全部归因为个人动作。

## 三、可迁移化改写（转岗核心）

1. **提炼底层能力**：销售 → 需求洞察、优先级、跨部门推进；运营 → 指标体系、实验设计。
2. **换成目标岗位的动词**：销售“跟进”→ 产品“拆解需求／定义验收”，但只换表达不换事实。
3. **给出可验证物**：作品集、仓库、文档、上线记录或真实使用说明。

自查：把原岗位名称删掉，这段能力证据还成立吗？成立，迁移才清楚。

## 四、禁忌词（提示空泛，不机械替换）

热爱、赋能、闭环、抓手、深耕、致力于、具备较强的、良好的沟通能力、熟练使用 Office、有责任心、抗压能力强、学习能力强、结果导向、owner 意识、从 0 到 1（除非确实一次建成）。

这些词用于检查是否缺少具体对象、动作和结果，不是命中即改。**用户确认的具体表述**、真实工具名和工作方式优先，但应补足事实，不机械删词。

## 五、篇幅与呈现逻辑

| 背景 | 建议页数 | 内容配比参考 |
|---|---|---|
| 应届／经验较少 | 1 页 | 教育、实践、项目、技能按证据分配 |
| 经验较丰富 | 1–2 页 | 工作优先，项目与教育技能服务定位 |
| 转岗 | 1–2 页 | 目标方向实践与可迁移证据优先 |

这是线框预算，不是硬性配额。工作通常按时间倒序；项目按目标岗位相关性优先，同等相关时按时间倒序与证据完整度排序。第二页留白较多时，判断该压缩、改一页还是保留呼吸感，不为填满而编内容。

## 六、公司与职位表述

- 保留正式职位；内部职位难懂时可补充通俗职责，不升级级别。
- 企业不知名时，可用一句话说明主营业务；“全球第一”等排名必须有可靠公开出处或统一口径。
- 不用公司宣传替代个人贡献，不因数字大就自动标蓝。

## 七、AI 与 Vibe Coding 项目

1. 写清项目状态：自用 MVP、内部工具、公开演示、真实用户或客户交付。
2. 写清本人动作：设计、开发、整合、测试、运营，不笼统写“用 AI 赋能”。
3. 公开演示使用合成数据时明确说明，不能将演示结果写成真实业务结果。
4. 工具订阅量、Token 消耗量只是辅助线索，优先写解决的问题、产物、验收和真实使用。
5. 链接必须有效；空仓库或过期页面不如不放。README 应说明为什么做、边界和验收，而非只堆技术名词。

## 八、交付前的三个问题

1. 有 JD 时如何回应目标岗位？没有 JD 时通用方向是否清楚？
2. 每条数字、角色和项目能否被追问三层？
3. 如果只留 5 行，留哪 5 行？用于形成标蓝 proposal，不自动替用户决定。
