# 运营纪律：确定性流程与阶段门禁

## 一、所有入口汇入同一主流程

| 请求形态 | 前置动作 | 汇入点 |
|---|---|---|
| 已有简历／仅简历 | 读取、审计、补齐关键缺口 | 结构线框 |
| 简历 + JD | 同上，另抽取 JD 要求 | 结构线框＋匹配方向 |
| 无简历／零散经历／只有 JD | 一轮集中问卷，少量缺失集中补问 | 结构线框 |
| 个人主页／GitHub／作品集 | 读取公开素材，集中确认归属和结果 | 结构线框或问卷 |
| 只换版式 | 已有确认后的定稿内容源 | 终排 |
| 只做体检 | 有 PDF 或 YAML | QA，不强制重建简历 |

**禁止路线菜单**：材料已经能判断时直接执行，不让用户选择“模式 A／B／C”。只有 JD 不代表有个人经历，只有链接也不代表可以跳过归属确认。

## 二、两次确认

| 门 | 名称 | 必须产出 | 通过条件 |
|---|---|---|---|
| G0 | 素材充分性检查 | 事实清单与集中问题 | 关键事实足够；不生成带 `【待补】` 的初稿 |
| G1 | **确认 1｜结构线框** | 页数、章节顺序、页面配比、阅读顺序、视觉方向、重点位置 | 用户确认结构后再写全文 |
| G2 | **确认 2｜全文文字稿** | 完整正文、标蓝／不标蓝清单；有 JD 时附差距表 | 用户确认正文与重点后再终排 |
| G3 | **终排与交付门禁** | 重新分页后的 PDF／源文件、QA 与视觉检查 | 可计算项通过＋真实渲染复核；未做项明示 |

用户明确要求“直接交付”可合并确认 1 与确认 2，但线框和全文仍须保留。终排若产生语义修改，回到确认 2，不借“已经确认过”绕过。

## 三、不跨阶段打包

- 不在素材不足时先编一份“待补简历”。
- 不在结构线框未确认时写整篇并渲染三套主题。
- 不在正文确认后机械套用旧线框；必须重新做终排。
- 一次只推进一个门，减少内容、结构与版式同时变化造成的返工。

## 四、责任源修复

| 症状 | 错误做法 | 正确做法 |
|---|---|---|
| 文字压到页边 | 手动加空格或缩小到难读 | 改换行宽度、密度或分页 |
| 某条读起来假 | 换更专业的同义词 | 回素材核实或删除推断 |
| 第二页太空 | 放大字号撑满 | 重新分页或压回一页 |
| 内容膨胀后拥挤 | 静默删字守页数 | 重新终排；语义删减回确认 2 |
| 换主题后别扭 | 继续加装饰 | 检查内容长度与层级 |

## 五、单一权威

冲突时按此顺序裁决：

1. 用户本次明确要求；
2. `references/content-rules.md`（内容）；
3. `references/design-system.md`（版式）；
4. 引擎默认值。

## 六、视觉复核是独立阶段

`qa.py` 只能查可计算问题。交付前用 `preview.py` 出图，逐页看：

1. **层级**：第一眼是否是姓名、定位和最重要证据？
2. **留白**：章节间距是否一致，内容膨胀后是否局部过挤？
3. **对齐**：日期右缘、正文左缘、图片中线是否一致？
4. **边缘**：有无孤字行、孤标题、贴边、压线、模糊图片和末页两三行？

任何一项不过，回到责任源修复，不把脚本通过等同于好看。
