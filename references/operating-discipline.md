# 运营纪律（从 ppt-master 提炼）

> ppt-master 值钱的不是模板，是它的**执行纪律**：确定性路由、阶段门禁、责任源修复。
> 本文件把这些纪律翻译成"做简历"的场景。原文是 MIT 许可（Copyright Hugo He），
> 这里只借方法，不搬内容。

## 一、两种默认模式，另支持换皮与体检

| 请求形态 | 前置条件 | 产出 |
|---|---|---|
| **仅简历优化** | 有一份可读取的简历 | 优化版 `resume.yaml` + PDF + 修改说明 |
| **简历 + JD 定制** | 有简历 + JD 原文 | 匹配版 YAML + PDF + 差距表 |
| **只换版式** | 有已定稿 YAML | 新 PDF（同内容） |
| **体检** | 有 PDF 或 YAML | `qa-report.txt` |

**禁止路线菜单**：请求已经能对上其中一行时，不要给用户列“你想走哪条”。选错了再改，比让他做选择题便宜。

**歧义只问一个判别问题**：例如“这份是投同一个岗位的新版本，还是另一个方向？”——问完就执行，不追问第二次。

## 二、缺信息时不伪造，也不把 JD 当启动条件

没有 JD 就走“仅简历优化”，直接提升结构、表达与版式；不要为了做“定制”逼用户补 JD。没有简历素材时才请用户补充，先给能完成的体检或草案，不用通用虚构内容顶上去。

## 三、阶段门禁（集中确认，不逐条折磨用户）

| 门 | 位置 | 通过条件 |
|---|---|---|
| G1 | 内容定稿前 | C 级推断、D 级缺失与归属问题已集中确认；普通 B 级用户陈述不逐条反复追问 |
| G2 | 渲染前 | 全文文字稿、章节取舍和标蓝 proposal 已给出；用户授权直接优化时可继续，但清单必须随交付保留 |
| G3 | 交付前 | `qa.py` 可计算项通过 + 真实渲染视觉复核；未做的验收项明确标注 |

**不替用户确认事实，不用提问代替交付。** 高影响问题合并一轮；低影响选择采用可逆默认并记录。

## 四、不跨阶段打包

- 不许边写内容边调版式：版式会掩盖内容的空洞。
- 不许提前准备下一阶段的产物（比如内容没定稿就先渲染三套主题）。
- 一次只推进一个门。

## 五、责任源修复

出问题时修**产生该产物的源头**，不许就地打补丁：

| 症状 | 错误做法 | 正确做法 |
|---|---|---|
| 文字压到页边 | 手动加空格 | 改排版引擎的换行宽度 |
| 某条读起来假 | 换同义词 | 回素材，删掉或补证据 |
| 第二页太空 | 放大字号撑满 | 补内容或压成一页 |
| 换主题后别扭 | 调主题 | 说明是内容问题 |

## 六、单一权威

冲突时按这个顺序裁决，不看"上次那版"：

1. 用户本次明确要求
2. `references/content-rules.md`（内容）
3. `references/design-system.md`（版式）
4. 引擎默认值

## 七、视觉复核是独立阶段

`qa.py` 只能查越界、页数、禁忌词这类**可计算**的问题；层级糊不糊、留白匀不匀，只能看。
所以交付前必须 `python scripts/preview.py out.pdf` 出 PNG，逐页看四项：

1. **层级**：闭眼再睁眼，第一眼看到的是不是姓名 + 定位？
2. **留白**：章节间距是否一致，有没有某段特别挤？
3. **对齐**：日期右缘、正文左缘、logo 中线，三条线齐不齐？
4. **边缘**：有没有孤字行、贴边、压线、logo 糊成一团？

四项里任何一项不过，回到对应源头（通常不是版式，是内容长度）。

## 八、交接要自包含

换一个 Agent 接手时，它不该需要这段对话。所以：
`resume.yaml` 自带全部内容，`SKILL.md` 自带全部规则，`qa-report.txt` 自带结论。
