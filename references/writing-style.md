# 简历写作、去套话与同题对照

## 目标

让招聘方看到具体、可信、可答辩的候选人。不要追求 AI 检测率、人味百分比或命中数归零；这些指标不能证明简历更有效。

结构性审查参考 Humanizer 4.0.0 的方法，按中文简历场景重新设计。原作者 Siqi Chen 的 MIT 许可见 `licenses/humanizer-LICENSE`。

## 先判断文体与读者

简历读者要快速判断岗位相关性、事实可信度和个人贡献。不要用自媒体固定开场、聊天口头禅、情绪化结尾或故意口语化来制造“人味”。专业术语、真实限制条件和用户确认过的措辞可以保留。

每条 bullet 先问：这句话提供了什么新的岗位判断信息？若只是强调重要、重复结论或装饰语气，直接写事实或删除。

## 结构模式，不是禁令堆积

按以下规律审查，命中后结合上下文处理：

| 模式 | 简历中的表现 | 处理规律 |
|---|---|---|
| 铺垫对比 | “不仅……更……”“不是……而是……”“与其……不如……” | 若负半句没有澄清真实误解，直接写动作与结果；归属对比可保留 |
| 戏剧化开场与总结 | “值得一提”“总的来说”“最重要的是” | 删除开场或重复总结，让事实自己承担重点 |
| 空泛深刻 | “核心是”“本质上”“底层逻辑” | 把所谓深刻判断换成可核验的具体关系 |
| 夸大意义 | “行业标杆”“里程碑”“重大突破”“广受好评” | 保留实际结果，删除无来源的重要性与宣传语 |
| 无名权威 | “专家认可”“业内领先”“客户一致认可” | 指明真实来源与口径；没有证据则不写 |
| 抽象三连 | “专业性、逻辑性、执行力”等抽象词排队 | 保留事实需要的项目数，不为了整齐凑三个抽象名词 |
| 连接号滥用 | 多个破折号代替明确句法 | 用逗号、句号或重写表达关系；日期范围与既有格式不受影响 |
| 堆叠限定 | “可能、基本上、一定程度上”连续出现 | 只保留事实需要的真实不确定性；暂定事实不得进终稿 |
| 装饰性强调 | 每条都加粗标签或强调 | 强调只服务岗位判断，不能代替内容层级 |
| 对话与草稿残留 | “希望这份简历……”“感谢您的阅读”“本简历旨在” | 从简历正文移除，不进入终稿 |
| 猜测性事实 | “大概参与”“据说是”“应该有” | 回到事实台账核实；不能核实就删除或省略 |

弱模式只给 `WARN`，不能自动替换。用户确认的原话若命中，保留并报告，不静默覆盖。

## 改前改后事实对账

纯润色前复制当前 YAML，润色后运行：

```bash
python scripts/content_audit.py revised.yaml --baseline before.yaml --json writing-audit.json
```

纯润色只允许 `bullet.text` 变化。事实台账、事实 ID、归属、URL、日期、章节结构和其他字段如需变化，退出纯润色，重新走证据与全文确认。

每条 bullet 的数字词元必须一致。数字对账通过不代表语义等价；公司名称、动作、范围、因果和限制条件仍需人工逐条阅读。报告中必须保留这项人工复核，不能写成“AI 已证明原意不变”。

## 可选的候选人表达样本

有用户本人写成的材料时，才提炼个人表达习惯；旧简历、聊天记录或用户确认的修改都可作为材料。文章建议的十篇样本**不是启动门槛**。样本不足时标低置信度，没有样本时使用中性专业风格。

提炼时记录：

1. 可统计特征：句长、常见标点、开头、转折和重复习惯。
2. 原文证据：每个规律附短例，不凭空生成口头禅。
3. `KEEP`：适合简历且用户希望保留的表达。
4. `CHANGE`：像用户但影响专业、简洁或真实性的习惯。
5. `ADD`：用户明确希望形成的新习惯，不把 Agent 的偏好冒充用户风格。

个人样本只覆盖弱风格倾向，不能覆盖事实、归属、固定视觉、真实 QA 或隐私边界。

## 同题对照与迭代

评估 Skill 本身时，固定同一原始材料、JD、模型、任务和页数约束，再比较：

- 无写作 Skill 的基线；
- 通用 Humanizer；
- 当前 resume-master。

产物可打乱为 A／B／C，由用户或目标读者按“事实保持、岗位相关、可答辩、简洁、自然”评价。自动测试、机械对账、Word 验收与人工盲评分别记录；未执行人工盲评时不得宣称已经胜出。

每次真实修改先问根因：是事实不清、读者不对、信息冗余，还是某种结构模式？把可泛化规律写入本文件或测试，删除已被新模型或新样本证明无效的规则，不只增不删。
