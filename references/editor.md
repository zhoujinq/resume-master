# 封板后交互微调工作台

## 何时使用

只有首个封板大版本的 DOCX、Microsoft Word PDF 和合格 QA 已完成，才进入本阶段。它不是初始排版路线，也不替代事实确认、写作复核或 Word 封板验收。

封板前仍是：事实 YAML → DOCX → Microsoft Word PDF。封板后，用户需要自行微调时，从同一最终 YAML 和已验收 PDF 派生单文件 HTML；原始封板文件保持只读。

## 生成

```bash
python scripts/editor.py resume.yaml --pdf resume.pdf --docx resume.docx --qa qa.json -o resume-editor.html
```

生成器会同时核对：

- YAML 和 PDF 都存在，PDF 必须对应同一最终版本；`--docx` 省略时取 PDF 同名文件。
- 封板 DOCX 与 YAML 做内容覆盖和段落数核对，作为最新导出的原位模板；错配必须停止，不静默重建另一套版式。
- `qa.json` 中核心与严格项没有 `FAIL` 或 `NOT_RUN`。
- 内容原子检查通过，YAML 中的正文在 PDF 中有覆盖。
- 记录 YAML 与 PDF 的 SHA-256，写入 HTML 和后续编辑备份。

如果候选人只有 PDF，没有最终 YAML：先提取候选结构，逐段人工确认阅读顺序、归属和文字，再建立 YAML 并走完整封板验收。不要按 PDF 坐标自动猜段落，也不要把提取文本直接当作已确认事实。

## 单文件与隐私

HTML 内联简历数据、运行时代码、JSZip 3.10.1 和可选照片。打开后不需要 CDN、外部字体或网络 API；简历正文只保存在用户自己的浏览器与下载文件中。

公开项目页只发布虚构样例。私人 HTML、JSON 备份和导出文件不得提交到公开仓库。

## 用户操作

- 直接点击简历文字修改；按钮或 `Ctrl+B` 对选中文本加粗／取消加粗。
- 选中文字后可改变局部颜色；全局强调色只影响当前个人副本。
- 字号、行距和段后距均按 **0.1pt** 调整，可选择当前段、同类段落或全文。
- 自动保存到 localStorage；同时提供 JSON 备份／恢复、重置封板原版。
- 数字发生变化时提醒重新核对事实、归属和时间；内容可能增页时提醒检查打印分页。
- 基 PDF 哈希不同的备份拒绝导入，避免把另一份简历的修改套过来。

localStorage 不是唯一备份。清理浏览器数据、换浏览器或换电脑前，必须下载 JSON 备份。

## 导出与精度

**Word**：以原封板 DOCX 为包模板，读取当前 DOM 和最新编辑状态，原位更新文字 Run、粗体、颜色、真实超链接和排版参数，保留原页边距、编号、图片及未修改部件；不是图片或旧封板文件的改名副本。结构映射不一致时明确停止导出。

**PDF**：点击“打印／另存为 PDF”，浏览器打印当前最新页面；用户在系统打印界面选择“另存为 PDF”。按钮不会导出旧的基 PDF。

HTML／浏览器 PDF 支持 0.1pt。标准 DOCX 的 `w:sz` 只能表示 0.5pt 字号，因此 9.7pt 会提示并导出为最近的 9.5pt；行距和段距用 twips 保存。不得宣称 DOCX 字号也支持无损 0.1pt。

导出前若有精度取整、数字变化或可能增页，必须如实提示，不能静默处理。

## 验收

自动测试必须覆盖：缺少 PDF、QA 阻断、错误 PDF、可选资料缺失、XSS／危险链接、0.1pt、DOCX 0.5pt 映射、最新文字导出、真实 ZIP／OOXML、图片、链接、数字提醒、备份与跨基哈希拒绝。

真实浏览器至少验证：文字微调、按钮与 Ctrl+B、选中文字变色、三级排版范围、刷新恢复、JSON 备份、DOCX 下载、打印入口和窄屏工具区。

真实 Microsoft Word 至少验证：打开浏览器下载的 DOCX、最新文字存在、链接与照片保留、临时副本编辑—撤销、导出 PDF 的文本层和逐页视觉、重复导出同 DPI 像素差为 0。

原生系统打印保存框若未实际操作，浏览器 PDF 文件级保存标为 `NOT_RUN`；不得拿 Word 从 DOCX 导出的 PDF 冒充浏览器 HTML 打印 PDF。
