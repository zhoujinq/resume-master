# 终排、交付与真实渲染验收

## 一、单一内容源与唯一排版源

所有格式来自同一份 `resume.yaml` 或等价结构化正文，不在不同格式里分别手改同一句话。事实变化先改源文件，再重新生成全部交付物。

“单一内容源”不等于“所有路线像素一致”：

- **Word 路线**：YAML → DOCX → Microsoft Word PDF；DOCX 是唯一排版源。
- **HTML 路线**：YAML → HTML → Chrome／Edge PDF；HTML 是唯一排版源。
- **ReportLab 路线**：YAML → PDF；是独立兜底，不与 Word／HTML 互相冒充。

默认交付 PDF＋可编辑源文件＋修改说明。用户要求 Word 时交付 DOCX＋同源 PDF＋YAML，不能用截图代替可编辑 Word。

## 二、内容定稿后必须重新终排

确认 2 后按真实字量重新评估页数、每页章节分配、内容膨胀、换行、孤标题、分页、末页留白、链接长度、照片和 Logo。非语义间距、密度和分页可修；删项目、改数字、压缩职责或其他语义变化必须返回确认 2。

不能为排版悄悄删字，不为填满第二页编造内容或放大字号。连续修补仍重叠、错位或分页异常时，回生成方法与内容长度修责任源，不用遮盖和手动空格糊住。

## 三、真实渲染才算验收

- PDF：检查页数、首末内容、越界、文本层、照片与 Logo、链接、末页留白。
- Word：用 Microsoft Word 打开并由同一 DOCX 导出 PDF，再比较归一化全文、重点、分页、照片、分隔线和链接。只看 OOXML 参数不算通过。
- 照片：行内图片所在段落不能继承会裁切图片的固定行距；只给显示宽度，高度等比。检查 PDF 实际图像，不拿原图像素代替导出结果。
- 字体：安装或注册不等于渲染器已识别；必须报告 PDF 实际字体。字体白名单是独立严格检查。
- 环境没有对应渲染能力时写 `NOT_RUN`，不能声称格式一致。

QA 失败先区分文档错误与比较器假失败。比较前统一空白、软连字符、破折号和页脚页码；只允许一个中文标点按 Word 排版规则悬挂到版心外，字母、数字或整行超宽仍是失败。

## 四、报告状态与结论

| 状态 | 使用规则 |
|---|---|
| `PASS` | 已执行且通过 |
| `WARN` | 已执行但有提醒 |
| `FAIL` | 已执行且未通过 |
| `NOT_RUN` | 未做，不能计入通过 |
| `NOT_APPLICABLE` | 本产物不适用 |

检查分三层：

1. **核心**：页数、越界、占位、源文覆盖、DOCX/PDF 文本一致性、可点击链接、文本层、逐页视觉复核等。
2. **严格**：字体白名单、重导出像素差为 0、实际 Word 编辑—撤销等。
3. **建议**：照片建议像素等。建议未达不冒充核心失败，也不被隐藏。

报告必须分别给核心、严格、建议和总体结论。核心通过但严格未做时，总体保持 `INCOMPLETE`；严格字面失败时不能写“全部通过”。不能仅凭测试数量宣称全部通过。

## 五、视觉、复现与编辑证据

1. `preview.py` 生成每页 PNG；Agent 逐页查看层级、留白、对齐、边缘、照片和分页后，才把证据路径传给 `--visual-evidence`。
2. 需要证明可复现时，用同一 DOCX、同一 Word 参数第二次导出，通过 `--repeat-pdf` 做同 DPI 逐页像素比较；像素差必须为 0。未做写 `NOT_RUN`。
3. 需要证明 Word 可正常编辑时，在副本中实际改一字、撤销、复核版式并保存证据；未做不能用“DOCX 可编辑”推断测试已过。
4. `--font-allow` 是严格白名单；未提供时只报告实际字体，不能宣称“只出现指定字体”。

## 六、修改说明与未决项

交付说明固定包含：

1. 我做了什么：素材、线框、正文、终排、路线与输出文件；
2. 事实依据、标蓝／不标蓝清单与省略内容；
3. 验收范围：核心、严格、建议、视觉和文件指纹；
4. 未做项与仍需用户复核的数字、术语、归属和线上风险；
5. 需要你什么：下一步必须判断的最小问题。

没做浏览器、Word、重导出或线上视觉验收时明确写 `NOT_RUN`，不把文件生成、测试数量或代码推送成功说成视觉验收完成。
