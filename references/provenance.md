# 改写边界与溯源

> 一条原则：**可以换说法，不可以换事实。**
> 本文件定义"哪些改写合法、哪些等于造假"，以及每条内容该标什么来源。
> 借鉴自 `resume-assistant` 的 provenance 规则，按本技能的分级体系重写。

## 一、四种来源标记

| 标记 | 含义 | 允许进入正式版 |
|---|---|---|
| `A` | 有凭据（合同、后台数据、证书、公开记录） | 直接写 |
| `B` | 用户口述，无凭据 | 写，但交付时列出"需你复核" |
| `C` | AI 推断（从上下文推的） | **必须用户逐条确认**，否则不许留 |
| `D` | 未知 | 写 `【待补】`，不许估 |

输出时可以用行内注释保留，也可以用单独的待确认清单承载。**没有第三条路。**

## 二、合法的 8 种改写

1. **同义替换**：负责 → 主导（仅当确实主导）；参与 → 协作（降级是允许的，升级不允许）
2. **结构重排**：把"动作在前"改成"判断在前"
3. **抽象层级调整**：把"跑了 36 家客户"归纳成"从 0 搭建区域客户网络"，同时保留数字
4. **单位换算**：45.3 万美元 → 约 322 万元人民币（须标注汇率与口径）
5. **删减**：删掉不相关经历（不做假，只是不写）
6. **归并**：三条碎经历合并成一条，但每条的贡献不能凭空放大
7. **语言迁移**：中文经历用英文岗位的语言重写（翻译 + 术语对齐，不加内容）
8. **术语对齐**：把内部叫法换成行业标准叫法（"大科研" → "高校与科研机构"）

## 三、禁止的 6 种改写（等于造假）

| 禁止 | 例子 |
|---|---|
| 升级角色 | 参与 → 主导 / 负责；协作 → 独立完成 |
| 加数字 | 原文没数字，写"提升 30%" |
| 扩范围 | 一个区域 → 全国；一个客户 → 一类客户 |
| 挪时间 | 把 3 个月写成半年，凑"一年经验" |
| 借他人成果 | 团队成果写成个人成果；同事的项目写进自己名下 |
| 补技术栈 | 没用过的模型/框架写进技能栏 |

## 四、升级/降级的方向性

**降级安全，升级危险。**

- 拿不准是否"主导" → 写"负责其中 XX 部分"，不写"主导"
- 拿不准是否"提升 30%" → 写"显著缩短"（但禁忌词表里没有"显著"，可以接受）或直接给原始数字
- 拿不准客户量级 → 写"某高校"，不写"头部高校"

这条规则的底层逻辑：**面试官追问三层，第三层一定问到边界。** 主动降级的人经得起追问，拔高的人经不起。

## 五、交付时必须附的东西

1. **待确认清单**：所有 B / C / D 级逐条列出，写明"需要你回答什么"
2. **改动说明**：这一版相对上一版改了什么、为什么改（不超过 5 条）
3. **不承诺**：不写"这样改能提高面试率"，只写"这样改解决了什么问题"
